# Motion & Shape

Shape tokens (radius, border, shadow) and motion durations/easing are
generated from
[`tokens/shape.json`](https://github.com/darroughw/freelancer/blob/main/tokens/shape.json)
via [Style Dictionary](https://styledictionary.com) the same way as
[Colors](?path=/docs/foundations-colors--docs) — added for the
typesafe.ai-inspired redesign's flat, hard-bordered "window-chrome" language,
which replaced the previous soft-shadow/rounded-card look.

Two values now, down from six — the redesign deliberately collapsed the
previous 4–12px spread of "soft card" radii into one small, barely-rounded
`$radius-sm`, leaving only the functional extremes: almost-square windows,
and full pill/circle shapes for anything meant to read as a button or tag.

## Elevation: hairline borders + one hard shadow

No soft, blurred `box-shadow` appears anywhere in the stylesheets anymore.
Depth comes from two things instead:

- **`$border-hairline`** (1px solid `$ink`) on every window-chrome element
  and flat card — the default resting state.
- **`$shadow-sticker`** (`3px 3px 0 var(--color-ink)`, a hard, unblurred
  offset shadow) on hover/focus for interactive cards — a deliberate,
  original addition for this site, not a literal pattern lifted from the
  typesafe.ai reference, whose own depth comes from z-stacking overlapping
  windows rather than any shadow at all.

## `prefers-reduced-motion`

No `@keyframes` animation exists in the stylesheets currently (the contact
section's photo treatment is a static halftone/duotone filter, not an
animated one). A single global override in `_a11y.scss` still kills every
transition site-wide — not per-component opt-outs — when the user has motion
reduction enabled at the OS level, ready to catch any animation added later:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
