## Notes

- **`red-text`** is a darker variant of `red` for small/normal-weight text on
  light backgrounds — `red` itself only clears WCAG AA contrast at large text
  sizes.
- **`red-deep`** is a darker variant of `red` for use as a background behind
  cream text — `red` itself only gives cream text ~4.0:1 contrast, below the
  4.5:1 AA threshold.
- The palette is defined in `oklch()` rather than hex so lightness and chroma
  stay perceptually consistent across hues.

## Theming: `[data-theme]`

Every token above is a CSS custom property (`--color-*`) on `:root`, not a
plain Sass value — Sass variables like `$red` just alias `var(--color-red)`.
That indirection is what lets the whole palette swap at runtime by setting an
attribute, with zero changes needed in the ~15 stylesheet partials that
consume `$red`, `$ink`, etc.

`ThemeToggle` flips `document.documentElement.dataset.theme` between
`"vhs"` and unset (persisted to `localStorage`), which selects between the
`:root` block above and this override:

  <ColorItem title="VHS · Ink" subtitle="The box's printed black" colors={{ ink: "oklch(0.19 0 0)" }} />
  <ColorItem
    title="VHS · Cream"
    subtitle="Paper white / a slightly darker variant, both from the box"
    colors={{ cream: "oklch(0.96 0.02 88)", "cream-dark": "oklch(0.92 0.03 89)" }}
  />

Each VHS token keeps the **same lightness (L)** as its default-theme
counterpart and only shifts chroma/hue — so every contrast ratio the a11y
audit verified against `red-text`/`red-deep` holds under either theme without
re-checking.
